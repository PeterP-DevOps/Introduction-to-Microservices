# Домашнее задание к занятию «Введение в микросервисы» - Петр Петров
### Задача 
Руководство крупного интернет-магазина, у которого постоянно растёт пользовательская база и количество заказов, рассматривает возможность переделки своей внутренней ИТ-системы на основе микросервисов.

Вас пригласили в качестве консультанта для оценки целесообразности перехода на микросервисную архитектуру.

Опишите, какие выгоды может получить компания от перехода на микросервисную архитектуру и какие проблемы нужно решить в первую очередь.
### Решение

Выгоды перехода на микросервисы:

- Точечное масштабирование — можно наращивать мощности только для нагруженных сервисов (например, для обработки заказов в пик сезона).
- Независимая разработка и деплой — команды работают параллельно, релизы выходят быстрее, не нужно пересобирать всю систему.
- Гибкость в выборе технологий — для разных задач можно использовать оптимальные стеки (например, Go для высоконагруженных API, Python для рекомендаций).
- Изоляция сбоев — если падает один сервис (например, уведомления), остальные продолжают работать.
- Проще поддерживать и тестировать отдельные части — меньше риска случайно сломать всю систему при доработке.
- 
Проблемы, которые нужно решить в первую очередь:

- Правильная декомпозиция — важно грамотно разделить систему на сервисы по бизнес-доменам, иначе получится «распределённый монолит» с теми же проблемами.
- Управление данными и согласованность — в микросервисах у каждого сервиса своя база; нужно продумать, как синхронизировать данные (например, через Saga или события).
- Надёжное взаимодействие сервисов — понадобятся механизмы обработки сетевых сбоев (таймауты, повторные попытки, Circuit Breaker), версионирование API.
- Зрелая DevOps‑инфраструктура — нужны оркестрация (например, Kubernetes), CI/CD, мониторинг, трассировка, сервис‑меш.
- Сложное тестирование и аналитика — труднее тестировать взаимодействие сервисов и собирать единые отчёты из разрозненных баз данных.
